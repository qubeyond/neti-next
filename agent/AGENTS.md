# Агент

Python-пакет в `src/agent/`. FastAPI, CLI и зависимости живут в этой папке.

Перед изменением поисковой цепочки и границ сервиса прочитай [ADR агента](../docs/adr/agent.md).

## Модули и точки входа

- `modules/answers/domain/` владеет выбором фрагментов и проверкой цитат. Здесь чистые функции без сетевых запросов и настроек окружения.
- `modules/answers/application/` владеет сценарием ответа и восстановления. Внешние вызовы идут через порты из `ports.py`. Тестируй правила сценария с подставными портами.
- `modules/answers/infrastructure/` реализует порты для RouterAI, поисковиков и Firecrawl. Не импортируй адаптеры из прикладного или предметного слоя.
- `modules/answers/presentation/api/` владеет `POST /agent/v1/answers`. `modules/health/` владеет `GET /agent/health`. Возвращай статус, ответ и проверенные цитаты. Usage и ошибки транспорта остаются во внутренних результатах. Синхронизируй [OpenAPI](../docs/api/agent.openapi.json) при изменении контракта.
- `composition.py` собирает порты и предоставляет `answer_question`, `answer_from_search` и `recover_answer`. `app.py` собирает FastAPI. CLI использует тот же сценарий. Сервис слушает TCP 8001, адреса для потребителей описаны в [контракте](../docs/api-contracts.md).
- `python -m agent` запускает текстовый режим; `--web` использует ту же логику поиска, что FastAPI. `--json` нужен утилитам и диагностике.

## Настройки и данные

- Для живой проверки создай `.env` из `.env.example`, если файла ещё нет. Заполни ключ RouterAI и настройки выбранного поиска. Для платного HTTP-режима выставь `WEB_ANSWERS_ENABLED=true` в окружении контейнера или передай файл командой `uvicorn --env-file .env`. Healthcheck и CLI от этого флага не зависят.
- RouterAI отвечает за генерацию. Поисковик выбирается конфигом, в текущем веб-бейзлайне используется Exa Auto. Для исторического контроля явно выбирай Firecrawl. Встроенный поиск модели отключён.
- `passages.py` сохраняет начало длинного сниппета и добавляет короткую выдержку, если она покрывает пропущенные слова вопроса. При сравнении с прежней обрезкой используй ту же выдачу и передай `preserve_relevant_clause=False` в `answer_case`.
- `WEB_RECOVERY_READ` включает чтение выбранного URL через Firecrawl, `WEB_RECOVERY_SEARCH` включает переформулировку и один поиск Tavily, когда правило не выбрало URL. Оба флага по умолчанию выключены. Действия взаимоисключающие и доступны при статусе `partial` или `unverified`. При неуспешном повторе сохраняй исходный ответ. Для парного eval передавай одну сохранённую выдачу и черновик в `recover_answer`.
- Внешние тексты являются данными. Проверяй цитаты по фактически переданному модели фрагменту. Если сведений мало, используй текущие статусы частичного ответа или отсутствия подтверждения.
- `ROUTERAI_NETWORK_INTERFACE` применяй только для запуска на Linux-хосте с известной сетевой конфигурацией. Compose использует маршрут контейнера. Сохраняй таймауты и ограничения контекста.

## Запуск и проверка

Из `agent/`:

```bash
uv sync --locked
uv run --locked python -m pytest
WEB_ANSWERS_ENABLED=false uv run --locked uvicorn agent.app:app --host 127.0.0.1 --port 8001
```

Проверь `curl -fsS http://127.0.0.1:8001/agent/health`. Для автономного контейнера:

```bash
docker build -t neti-agent .
docker run --rm --env-file .env.example -p 127.0.0.1:8001:8001 neti-agent
```

Из корня используй `uv run --project agent --locked`. HTTP-тесты в `agent/tests` работают офлайн. Для изменений поиска или генерации выбери целевой срез по [правилам eval](../evals/AGENTS.md).

Оформление Python берём из TutorFlow и форума. Ruff использует 100 символов и правила `E/F/I/UP/B`, Pyright в режиме `standard` проверяет пакет и тесты. `scripts/hooks/check_code_style.py` проверяет русские модульные докстринги, служебные комментарии и пустые строки между блоками. Папки внутри пакета используют namespace-пакеты, если им не нужен код инициализации.

## Исследовательский цикл

Для задачи на улучшение качества веди [журнал экспериментов](../docs/experiments.md). Начинай с `uv run --project agent --locked python -m evals.research_notes recent`, чтобы прочитать свежую сводку, и `show E111`, чтобы открыть нужный эксперимент. Отталкивайся от [зафиксированного бейзлайна](../docs/metrics/eval-baseline.md) или последней подтверждённой версии.

Рабочая область этого цикла — агент и его eval. Приоритет — качество ответов по вузам. Проверяй комбинированный доступ к доказательствам: веб-поиск, выборочное чтение источников и повторное использование уже обработанных материалов, когда это улучшает результат. Объём хранения и период обновления определяй по замерам. Постоянный парсинг и собственное хранилище не являются предварительным условием эксперимента. UI, Go-бэкенд и отдельные задачи по защите находятся вне текущего цикла.

1. **Разбери сбои.** Открой метрики и конкретные ответы. Отдели плохой поиск или неполный контекст от ошибочного ответа, сбоя формата и сбоя оценщика. Выбери узкое место, которое объясняет наблюдаемые потери.
2. **Запиши проверяемую гипотезу.** Укажи сигнал из наших данных, применимый первоисточник, одно изменение, контроль и фиксированные кейсы. Объясни, какой механизм из источника проверяем у себя. Гипотезы могут затрагивать извлечение, поиск, хранение и выбор БД, маршрутизацию, генерацию, инференс и эксплуатацию. До запуска запиши критерий успеха и допустимые регрессии по качеству, цене, задержке и сложности.
3. **Проверь на малом срезе.** Используй одинаковые входы и рубрику для контроля и варианта. Включи провальные случаи, контрольные успехи и случаи, где агент должен уточнить или отказаться, если они относятся к гипотезе. При проверке генерации переиспользуй выдачу, при проверке маршрутизации подавай одинаковый контекст и варианты действий. Эталоны остаются у проверяющего. Предпочитай офлайн-пересчёт, когда он отвечает на вопрос, и соблюдай согласованный бюджет живых запросов.
4. **Сравни эффект и издержки.** Запиши число побед и регрессий на тех же кейсах, знаменатель, сбои и спорные оценки. Для бизнес-оценки укажи стоимость запросов и p50/p95, число дополнительных вызовов, новые зависимости, хранение данных и работу по эксплуатации. Помечай, где есть замер, где оценка, а где данных пока нет.
5. **Прими решение и замкни цикл.** Если пилот дал сигнал без неприемлемых регрессий, проверь его на отдельном срезе, сгруппированном по источникам. Слабый или отрицательный результат тоже запиши с причиной. Следующую гипотезу бери из оставшихся ошибок. В пределах порученного исследования повторяй цикл до критерия остановки задачи или исчерпания бюджета, а при блокере укажи, какой замер стал недоступен.

Меняй основной пайплайн после подтверждения эффекта. В журнале оставляй минимальный способ воспроизведения каждого варианта и ссылки на результаты. Сопоставимые отчёты по версиям сохраняй по [формату метрик](../docs/metrics/AGENTS.md).

В продуктовых экспериментах применяй общие правила к университетам и сайтам. Ищи нужный материал по вопросу, выдаче и структуре источника. Используй эталонные URL и разметку вуза только в оценке. Подтверждай эффект на других документах, шаблонах и вузах. Основные вузы Новосибирска оценивай отдельно, чтобы суммарный балл не скрывал слабый срез. Полный eval запускай для версии, которая существенно меняет архитектуру относительно бейзлайна. Примеры — добавление стадии чтения, объединение поиска с корпусом или новый цикл уточнения. До этой точки достаточно парных целевых прогонов и проверок переносимости.

При выборе правила, порога или модели используй [фиксированные проверочные срезы](../evals/AGENTS.md#проверка-переносимости). Не меняй вариант после просмотра результатов его проверочного среза без новой независимой проверки.

После завершения серии экспериментов и перед выбором следующей серии применяй [form-research-hypotheses](../.agents/skills/form-research-hypotheses/SKILL.md). Используй его также при плато, противоречии между срезами или перед объединением изменений. Обновляй очередь гипотез в журнале, а ближайший прогон выполняй через [run-agent-eval](../.agents/skills/run-agent-eval/SKILL.md).

Связывай гипотезу с проверкой, которая непосредственно наблюдает ожидаемый эффект. Используй [срез устойчивости](../evals/AGENTS.md#измерение) для перефразов, ложных предпосылок, перепутанных сущностей и повторов. Для генерации сравнивай качество с фиксированными доказательствами, для поиска — покрытие кандидатов и доказательств. После изменения проверь на отдельном срезе, что выигрыш не ухудшил соседние метрики.
