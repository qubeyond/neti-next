# Развёртывание

Общие команды, Compose и выкладка принадлежат этой папке. Настройки каждого приложения принадлежат соответствующему сервису.

Перед изменением окружений или выпуска прочитай [ADR развёртывания](../docs/adr/deploy.md).

## Локальная разработка

| Команда из корня | Действие |
| --- | --- |
| `make -C deploy setup` | Создаёт отсутствующие файлы окружения, устанавливает lockfile-зависимости и Git-хуки. |
| `make -C deploy dev` | Собирает и поднимает стек. Фронтенд доступен на `127.0.0.1:8080`. |
| `make -C deploy dev SERVICES=agent` | Поднимает выбранный контейнер. Для агента и Go эта команда сама не открывает порт на хосте. |
| `make -C deploy logs` / `make -C deploy down` | Логи или остановка локального стека. |
| `make -C deploy check` | Тесты, Ruff, проверка стиля, Pyright, сверка OpenAPI, TypeScript, сборка и валидация Compose. |
| `make -C deploy smoke` | Собирает обе конфигурации на временных портах и проверяет React, Go, FastAPI и CLI. |

- `compose.yaml` — runtime. `compose.dev.yaml` добавляет локальные исходники и перезагрузку React и FastAPI. Go пересобирается при `dev`. `compose.build.yaml` используется для smoke production-образов.
- Положи настройки в `frontend/.env`, `backend/.env` и `agent/.env`. Compose подставляет их раздельно. `APP_BIND` и `APP_PORT` относятся к стеку; например `APP_PORT=8081 make -C deploy dev`.
- Smoke читает примеры окружений, создаёт свой проект Compose и останавливает только его. Сохраняй возможность проверять все контейнеры и прокси без ключей.
- Сервисы должны собираться из собственной папки. Изменение границ проверь отдельной сборкой из скопированной папки. При переносе обнови upstream во фронтенде или у вызывающего сервиса.
- `pre-commit` проверяет изменённые файлы и применяет безопасные исправления оформления. `pre-push` запускает `make -C deploy check`. Конфигурация находится в [корне репозитория](../.pre-commit-config.yaml).

## Сеть агента

- В стеке адрес агента — `http://agent:8001`. На хост агент порт не публикует. UI обращается через существующие прокси-маршруты. Запросы и статусы описаны в [HTTP-контракте](../docs/api-contracts.md#подключение-к-агенту).
- Для отдельного Compose-проекта создай выделенную сеть `docker network create neti-agent`. При запуске стека вручную добавь `-f deploy/compose.agent-network.yaml` после основного Compose и нужного overlay. Переменная `AGENT_DOCKER_NETWORK` переопределяет имя сети.
- Включи сеть в Compose потребителя как `external: true`, `name: neti-agent`, добавь её к сервису-клиенту и обращайся на `http://neti-agent:8001`.
- При штатной выкладке можно присоединить доверенного потребителя к существующей сети `neti-next_default` и использовать `http://agent:8001`. Такая сеть даёт доступ и к другим сервисам стека, поэтому для подключения только к агенту используй выделенную сеть при ручном запуске.

## GitHub Actions и production

- `CI` запускает проверки и dev/prod smoke для PR и обновлений `dev`. Выпуск трёх образов в GHCR с одним тегом SHA доступен при ручном запуске `CI` из `dev`.
- В `dev` вливай изменения через PR. Обязательные проверки — `Checks`, `Compose smoke (dev)` и `Compose smoke (prod)`. GitHub включает squash auto-merge для готовых PR от участников из веток этого репозитория.
- Закрепляй Actions по полному SHA. Отключай сохранение checkout-credentials и предоставляй права записи только задачам публикации. Примеры окружений допустимы в образах только как документация; рабочие env подаются при запуске.
- На сервере установи Docker с Compose v2 и подготовь пользователя с доступом к каталогу релизов и pull из GHCR. Сохрани параметры стека в `stack.env` из [шаблона](.env.example). При необходимости добавь `frontend.env`, `backend.env` и `agent.env` из сервисных шаблонов; файл агента с ключами защищай правами `600`.
- Для автоматической выкладки установи repo variable `DEPLOY_ENABLED=true`. `PROD_SSH_DIR` задаёт каталог, стандартный путь — `/srv/neti-next`. В environment `production` задай `PROD_SSH_HOST`, `PROD_SSH_USER`, `PROD_SSH_KEY`, `PROD_SSH_KNOWN_HOSTS`. Проверяй ключ хоста через доверенный источник.
- Публикуй наружу фронтенд через доверенный TLS-прокси. Прежде чем включать платные HTTP-ответы агента в production, ограничь доступ на внешнем шлюзе.
- `activate.sh` скачивает образы, ждёт healthcheck и меняет указатель `current` при успехе. При неудачной активации поднимает предыдущий релиз и возвращает ошибку. Для отката на уже установленный SHA повторно вызови его `releases/<SHA>/activate.sh <каталог> ghcr.io/qubeyond/neti-next <SHA>`.
