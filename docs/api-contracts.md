# HTTP-контракты

Правила для бэкенда и агента. Рабочий контракт хранится рядом с изменением в Git, чтобы потребители могли сверить версию.

## Владельцы и публикация

| Сервис | Область | Как получить OpenAPI |
| --- | --- | --- |
| Go | `/api/…` | Обнови [OpenAPI бэкенда](api/backend.openapi.json) вместе с маршрутом и проверь через HTTP-тест. |
| FastAPI | `/agent/…` | Экспортируй `agent.app.app.openapi()` локально. Экспорт не требует сервера или ключей. [OpenAPI агента](api/agent.openapi.json). |
| Inference | `/inference/…` | Экспортируй `inference.app.app.openapi()` из каталога `inference` с `PYTHONPATH=src`. [Внутренний OpenAPI](api/inference.openapi.json). |

- При добавлении или изменении маршрута для клиента или другого сервиса обновляй машиночитаемый снимок владельца в том же PR. Снимки лежат в `docs/api/`. Зафиксируй ссылку на опубликованный снимок, если он нужен внешнему потребителю.
- Держи публичную спецификацию отдельно от внутренней диагностики. Для публикации используй Git по конкретному SHA или артефакт согласованного релиза. Открытие сетевых маршрутов Swagger или OpenAPI согласуй отдельно.
- Для FastAPI из корня экспортируй схему в файл для сверки. Путь назначения выбирай явно.

```bash
uv run --project agent --locked python -c 'import json; from agent.app import app; print(json.dumps(app.openapi(), ensure_ascii=False, indent=2, sort_keys=True))' > docs/api/agent.openapi.json
```

## Подключение к агенту

| Потребитель | Базовый адрес |
| --- | --- |
| Go или другой доверенный контейнер того же Compose-проекта | `http://agent:8001` |
| Контейнер другого проекта на общей выделенной сети | `http://neti-agent:8001` |
| Контейнер другого проекта, подключённый к основной сети NETI Next | `http://agent:8001` |

Сеть должна быть доступна обоим контейнерам на одном Docker-хосте. Способы подключения описаны в [инструкции развёртывания](../deploy/AGENTS.md#сеть-агента). `localhost` внутри контейнера относится к самому контейнеру.

| Метод | Вход | Результат |
| --- | --- | --- |
| `GET /agent/health` | — | `200 {"status":"ok"}`, без обращения к провайдерам |
| `POST /agent/v1/answers` | Вопрос от 1 до 2000 символов, необязательное вложение и контекст чата | `200`, поля `status`, `answer` и `citations` |

Каждая цитата содержит `url` и `quote`. Опциональный `ref` связывает маркер `〔n〕` с цитатой и календарной записью. Для фотографии `url` пуст, `attachment_id` указывает на вложение текущего диалога. Go может добавить `region` с координатами 0–1 при однозначном совпадении строки OCR. В `events` попадают дедлайны с полной датой в проверенной веб-цитате. Статусы `answered`, `partial`, `unverified` и `clarification` описывают результат хода. Ошибки запроса и провайдера возвращаются по общему контракту. Для доверенного потребителя включи `AGENT_TOKEN`. Платный обработчик включается через `WEB_ANSWERS_ENABLED=true` в окружении агента.

Вызов синхронный. Агент работает с переданным срезом истории, который хранит Go. Повтор запроса может повторно обратиться к платным провайдерам. Сервисная сеть предполагает доверенных потребителей, для внешнего доступа применяй политику доступа шлюза.

## Инференс

Go и агент по умолчанию обращаются к `http://inference:8002` в Compose. Код загрузки вложений проверяет владельца файла в Go. Браузер вызывает только API Go. При отдельной выкладке передавай одинаковый `INFERENCE_TOKEN` сервису и доверенным клиентам. Настраивай `INFERENCE_URL` на защищённый адрес сервиса.

| Метод | Назначение |
| --- | --- |
| `GET /inference/health` | Проверка процесса без платных вызовов. |
| `GET /inference/v1/capabilities` | Модели и доступные возможности. |
| `GET /inference/metrics` | Метрики Prometheus, включая гистограмму задержки `neti_inference_duration_seconds`, токены и расход. |
| `POST /inference/v1/generate` | Генерация по сообщениям с ограничением токенов. Агент может передать необязательные OpenAI-совместимые `tools` и `tool_choice`. Вызовы модели возвращаются в `tool_calls`, исполняет их клиент. |
| `POST /inference/v1/decide` | Выбор одного из 2–8 вариантов. Клиент передаёт `state`, `instructions` и карту `choices`. Инференс проверяет выбранный ключ и возвращает `choice`, модель, расход и задержку. |
| `POST /inference/v1/transcribe` | Готовый аудиофайл в base64, текст и сведения об использовании. |
| `POST /inference/v1/ocr` | Изображение или подготовленная PDF-страница в base64. Текстовый слой, выбор страниц и признак усечения документа принадлежат Go. |

Распознанный текст вложения передаётся агенту отдельно от поискового запроса. Для явного вопроса о приложенной фотографии Go отправляет `image_source`, и агент отвечает по её распознанному тексту без веб-поиска. Ответы инференса содержат `X-Request-ID`, который связывает HTTP-запись и операцию в JSON-логах. Внутренние операции могут вернуть `401` при неверном токене, `413` при превышении размера, `415` при неподходящем типе файла, `429` при перегрузке, `502` при сбое провайдера или `503` при отсутствующем ключе.

## Рабочее пространство

Профиль использует cookie `neti_session`. Гость получает короткоживущий токен для `Authorization: Bearer <token>`. Для WebSocket клиент предлагает подпротокол `neti.v1`, а гость добавляет `guest.<token>`. В URL токен не передаётся. WebSocket уведомляет о смене состояния. После события клиент запрашивает актуальный диалог или список диалогов по HTTP. [Схема](api/backend.openapi.json).

Go запускает обработку асинхронно. `202` подтверждает сохранение вопроса и выдаёт идентификатор будущего ответа. Сбой провайдера отображается в `state: failed` у сообщения. Текущее подключение к FastAPI и недостающие данные для следующей версии описаны в [задаче](tasks/workspace.md#передача-команде-агента).

## Проверка изменений

- Опиши параметры и тело, обязательность полей, ограничения, ответы и ошибки, а также аутентификацию, если она есть. Примеры должны использовать вымышленные данные.
- Сверь OpenAPI с фактическими статусами, телами ответов и потребителями. В FastAPI явно объявляй ошибки, которые обработчик возвращает через `HTTPException`, если генератор их пропускает. Для изменения прокси проверь оба режима из [deploy/AGENTS.md](../deploy/AGENTS.md).
- Для несовместимых правок укажи затронутые вызовы, переходный период или новую версию и порядок обновления клиентов. Обнови клиентские типы или пример вызова в том же PR.

## Ошибки и бюджет хода

- Сервисы возвращают [Problem Details](https://www.rfc-editor.org/rfc/rfc9457.html) с типом `urn:neti:problem:<code>`, полями `title`, `status`, `detail`, `request_id` и заголовком `X-Request-ID`. Ошибки валидации могут содержать безопасные координаты полей в `errors`.
- Внутренние вызовы передают `X-Request-ID` и `X-Deadline-Ms`. Дедлайн — Unix-время в миллисекундах. Каждый сервис ограничивает его своим локальным бюджетом. Для перегрузки используется `429`, для истёкшего бюджета — `504`. Ответы с ошибками не кешируются.
- Валидация и ошибки провайдеров отделены от результата QA. Ответ без подтверждения возвращается как `200` со статусом `unverified`. Повтор не должен обходить квоту или создавать второй ответ для того же идентификатора сообщения.

### Контекст, отмена и перегрузка

- В `POST /agent/v1/answers` можно передать `history` из 16 реплик `user` и `assistant`, до 800 символов каждая, и отдельный `quoted_text` до 1200 символов. Лимит тела запроса 128 КиБ. Последние восемь реплик доступны модели в исходном порядке, более старые агент может сжать в краткую заметку о текущей задаче. Для уточнения агент возвращает `200` со статусом `clarification` и пустыми цитатами.
- `POST /api/v1/chats/{chat}/messages/{message}/cancel` принимает отмену активного ответа владельца чата. Окончательное состояние приходит через событие чата. В ошибочном сообщении используется то же тело Problem Details в поле `problem`; поле `error` поддерживается для старых сообщений.
- В production `activate.sh` создаёт ключи внутренних сервисов в закрытом каталоге при отсутствии ключей владельца. Для заранее подготовленных ключей передай совпадающий `AGENT_TOKEN` Go и агенту, а `INFERENCE_TOKEN` Go, агенту и inference.

## Трассировка и черновик

`GET /api/v1/demo` проверяет доступ по ID аккаунта. `POST /api/v1/demo/runs` принимает вопрос и до шести реплик текущего демо, переданных клиентом. Для файла отправь multipart с текстовым полем `input` (JSON) и одним полем `file`. Ответ идёт в NDJSON без записи в историю. Типы строк — `span_start`, `span_end`, `heartbeat` и финальная `answer` или `error`. Записи связаны `request_id`, шаги — `id` и `parent`. `at_ms` измеряет момент получения события в Go, а `duration_ms` — длительность самого шага. После открытия потока ошибки идут финальной строкой. Внутренний поток агента требует сервисного токена.

Обычный чат может запросить у `POST /agent/v1/answers` формат `Accept: application/x-ndjson`. Поток использует те же правила доступа, что и JSON-ответ. Для этапа доступны ID, измеренная продолжительность, поисковик, домены, ID выбранных навыков и до трёх коротких фрагментов публичных страниц. Последняя запись содержит `answer` или `error`. Публичный API Go возвращает состояние этапа и `durationMs` в `messages[].activity`. Поле `elapsedMs` показывает положение этапа от начала хода.

Завершение этапа `select_skills` содержит `active_skills` со списком ID выбранных инструкций. Текст шаблонов в поток не передаётся.

`POST /api/v1/drafts/transcribe` принимает аудиофайл и возвращает `text`. Доступен пользователю с профилем и гостю, использует общий лимит ходов. Запись не отправляется как сообщение. Поля `suggestions` и `blocks` в ответе чата опциональны. Блоки `table`, `office` и `edition` передают столбцы и ячейки с номерами цитат. Блок `calculation` содержит операнды, ссылки на их доказательства и вычисленный итог. Блок `gap` описывает недостающее условие или следующий шаг.
