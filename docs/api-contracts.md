# HTTP-контракты

Правила для бэкенда и агента. Рабочий контракт хранится рядом с изменением в Git, чтобы потребители могли сверить версию.

## Владельцы и публикация

| Сервис | Область | Как получить OpenAPI |
| --- | --- | --- |
| Go | `/api/…` | Обнови [OpenAPI бэкенда](api/backend.openapi.json) вместе с маршрутом и проверь через HTTP-тест. |
| FastAPI | `/agent/…` | Экспортируй `agent.app.app.openapi()` локально. Экспорт не требует сервера или ключей. [OpenAPI агента](api/agent.openapi.json). |

- При добавлении или изменении маршрута для клиента или другого сервиса обновляй машиночитаемый снимок владельца в том же PR. Пути для снимков — `docs/api/backend.openapi.json` и `docs/api/agent.openapi.json`. Зафиксируй ссылку на опубликованный снимок, если он нужен внешнему потребителю.
- Держи публичную спецификацию отдельно от внутренней диагностики. Для публикации используй Git по конкретному SHA или артефакт согласованного релиза. Открытие сетевых маршрутов Swagger или OpenAPI согласуй отдельно.
- Для FastAPI из корня экспортируй схему в файл для сверки. Путь назначения выбирай явно.

```bash
uv run --project agent --locked python -c 'import json; from agent.app import app; print(json.dumps(app.openapi(), ensure_ascii=False, indent=2, sort_keys=True))' > docs/api/agent.openapi.json
```

## Подключение к агенту

| Потребитель | Базовый адрес |
| --- | --- |
| Go, фронтенд или другой контейнер того же Compose-проекта | `http://agent:8001` |
| Контейнер другого проекта на общей выделенной сети | `http://neti-agent:8001` |
| Контейнер другого проекта, подключённый к основной сети NETI Next | `http://agent:8001` |

Сеть должна быть доступна обоим контейнерам на одном Docker-хосте. Способы подключения описаны в [инструкции развёртывания](../deploy/AGENTS.md#сеть-агента). `localhost` внутри контейнера относится к самому контейнеру.

| Метод | Вход | Результат |
| --- | --- | --- |
| `GET /agent/health` | — | `200 {"status":"ok"}`, без обращения к провайдерам |
| `POST /agent/v1/answers` | `{"question":"Где найти расписание?"}`, 1–2000 символов после обрезки | `200`, поля `status`, `answer` и `citations` |

Каждая цитата содержит `url` и `quote`. Статус `answered`, `partial` или `unverified` описывает полноту ответа. Невалидное тело возвращает `422`, недоступный провайдер или невалидный ответ модели — `502`, выключенные веб-ответы — `503`. Платный обработчик включается через `WEB_ANSWERS_ENABLED=true` в окружении агента.

Вызов синхронный и не хранит историю. Повтор запроса может повторно обратиться к платным провайдерам. Сервисная сеть предполагает доверенных потребителей, для внешнего доступа применяй политику доступа шлюза.

## Рабочее пространство

Профиль использует cookie `neti_session`. Гость получает короткоживущий токен для `Authorization: Bearer <token>`. Для WebSocket клиент предлагает подпротокол `neti.v1`, а гость добавляет `guest.<token>`. В URL токен не передаётся. WebSocket уведомляет о смене состояния. После события клиент запрашивает актуальный диалог или список диалогов по HTTP. [Схема](api/backend.openapi.json).

Go запускает обработку асинхронно. `202` подтверждает сохранение вопроса и выдаёт идентификатор будущего ответа. Сбой провайдера отображается в `state: failed` у сообщения. Текущее подключение к FastAPI и недостающие данные для следующей версии описаны в [задаче](tasks/workspace.md#передача-команде-агента).

## Проверка изменений

- Опиши параметры и тело, обязательность полей, ограничения, ответы и ошибки, а также аутентификацию, если она есть. Примеры должны использовать вымышленные данные.
- Сверь OpenAPI с фактическими статусами, телами ответов и потребителями. В FastAPI явно объявляй ошибки, которые обработчик возвращает через `HTTPException`, если генератор их пропускает. Для изменения прокси проверь оба режима из [deploy/AGENTS.md](../deploy/AGENTS.md).
- Для несовместимых правок укажи затронутые вызовы, переходный период или новую версию и порядок обновления клиентов. Обнови клиентские типы или пример вызова в том же PR.
