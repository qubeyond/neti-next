# ADR развёртывания

## DEP-01 · Общий стек и автономные сборки

- **Дата и статус** — 2026-11-20, принято.
- **Контекст** — Команда работает в одном репозитории и хочет переносить отдельные сервисы независимо.
- **Решение** — Общий Compose, Makefile и скрипты находятся в `deploy/`. У каждого сервиса свой build context, Dockerfile и env. В полном стеке только фронтенд публикует порт, по умолчанию на loopback.
- **Последствия** — Один запуск для разработки, раздельная сборка и передача конфигурации. Секреты RouterAI и Firecrawl получает только агент. При переносе сервиса требуется адрес и доступ на стороне потребителя.
- **Пересмотр** — При появлении общей инфраструктуры, которой нужен самостоятельный жизненный цикл, например хранилища.

## DEP-02 · Выпуск по SHA и активация после CI

- **Дата и статус** — 2026-11-20, принято.
- **Контекст** — Одна версия кода должна соответствовать версии трёх образов и доступному откату.
- **Решение** — После успешных проверок `main` публикует образы в GHCR с тегом полного SHA. Серверная активация управляется переменной и выполняется по SSH с проверкой ключа хоста. Скрипт переключает `current` после healthcheck.
- **Последствия** — Единый идентификатор сборки облегчает диагностику. Продакшен требует отдельной конфигурации и готового сервера. При ошибке активации восстанавливается предыдущий установленный релиз.
- **Пересмотр** — При добавлении миграций или состояния нужно отдельно проверить совместимость отката.
