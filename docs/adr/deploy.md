# ADR развёртывания

## DEP-01 · Общий стек и автономные сборки

- **Дата и статус** — 2026-11-20, принято.
- **Контекст** — Команда работает в одном репозитории и хочет переносить отдельные сервисы независимо.
- **Решение** — Общий Compose, Makefile и скрипты находятся в `deploy/`. У каждого сервиса свой build context, Dockerfile и env. В полном стеке только фронтенд публикует порт, по умолчанию на loopback.
- **Последствия** — Один запуск для разработки, раздельная сборка и передача конфигурации. Секреты RouterAI и Firecrawl получает только агент. При переносе сервиса требуется адрес и доступ на стороне потребителя.
- **Пересмотр** — При появлении общей инфраструктуры, которой нужен самостоятельный жизненный цикл, например хранилища.

## DEP-02 · Выпуск по SHA и активация после CI

- **Дата и статус** — 2026-11-20, принято.
- **Контекст** — Одна версия кода должна соответствовать версии трёх образов и доступному откату.
- **Решение** — Публикация образов в GHCR с тегом полного SHA запускается вручную через workflow `CI` на `dev` после проверок. Серверная активация управляется переменной и выполняется по SSH с проверкой ключа хоста. Скрипт переключает `current` после healthcheck.
- **Последствия** — Единый идентификатор сборки облегчает диагностику. Продакшен требует отдельной конфигурации и готового сервера. При ошибке активации восстанавливается предыдущий установленный релиз.
- **Пересмотр** — При добавлении миграций или состояния нужно отдельно проверить совместимость отката.

## DEP-03 · Интеграция через pull request в dev

- **Дата и статус** — 2026-11-21, принято.
- **Решение** — `dev` используется по умолчанию и принимает только PR с прошедшими проверками. Для готовых PR из веток участников репозитория используется squash auto-merge без обязательного ревью. `main` хранит пустой снимок и защищён от обновлений.
- **Проверка** — GitHub применяет правила веток и обязательные проверки. Workflow автослияния работает с метаданными PR и не запускает код из его ветки.

## DEP-04 · Данные бэкенда и прокси событий

- **Дата и статус** — 2026-11-21, принято.
- **Решение** — Go пишет базу в том `backend-data`. Прокси фронтенда поддерживает WebSocket на `/api/v1/events` и загрузку файлов по `/api`. Адрес агента задаёт окружение Go.
- **Последствия** — При обновлении контейнера Compose данные профилей остаются в томе. Гостевые данные теряются при перезапуске Go. Рабочая база принадлежит одному процессу.
- **Пересмотр** — При смене формата данных или масштабировании проверить восстановление из копии и откат версии.
