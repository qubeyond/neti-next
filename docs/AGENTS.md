# Документы

Здесь хранятся требования к продукту, материалы трека и отчёты с результатами измерений.

## Индекс

- [Этапы](stages.md) — состояние, зависимости и критерии завершения.
- [Рабочий процесс](workflow.md) и [шаблон задачи](tasks/template.md) — порядок работы и передачи.
- [HTTP-контракты](api-contracts.md) — OpenAPI, совместимость и публикация для потребителей.
- [Метрики по версиям](metrics/AGENTS.md) — формат отчётов и веб-бейзлайн.
- ADR по владельцам — [агент](adr/agent.md), [бэкенд](adr/backend.md), [фронтенд](adr/frontend.md), [развёртывание](adr/deploy.md), [eval](adr/evals.md).

## Обновление

- В [описании трека](track.md) фиксируй формулировку кейса и баллы по материалам организаторов. Указывай источник и помечай открытые вопросы.
- В [спецификации](spec.md) описывай согласованное поведение и проверяемые критерии приёмки. Архитектурные предложения отмечай как решения команды со своими основаниями.
- После изменения статуса обнови соответствующую строку этапа и укажи доказательство готовности. Для повторяемых правок смотри [навык обновления документов](../.agents/skills/update-project-docs/SKILL.md).
- Храни один факт в одном месте. Ссылайся на исходный документ и проверяй относительные ссылки после перемещения файлов.
