# Think-About-It-Agent

Агент отвечает на вопросы о вузах Новосибирска по открытым данным и учитывает контекст диалога. Примеры тем — образовательные программы, поступление, условия обучения, общежития и студенческие сервисы. Формулировка и критерии организаторов приведены в [описании трека](track.md). Статус работ ведётся в [этапах](stages.md).

## Поведение и критерии приёмки

| ID | Требование | Как проверить |
| --- | --- | --- |
| DATA-01 | Агент использует базу знаний из открытых материалов вузов. Для каждого загруженного документа сохраняются источник, вуз, принадлежность к кампании или учебному году, если они указаны, и дата получения. | Показать сводку по обработанным документам и вузам. Из записи в индексе открыть страницу или документ, из которого взят фрагмент. |
| RAG-01 | По вопросу извлекаются релевантные фрагменты из базы знаний. При поиске учитываются вуз, филиал, период и другие явные условия. | Проверить нахождение нужной таблицы, документа и фрагмента. Заменить год или филиал в вопросе и проверить, что поиск учитывает изменение. |
| ANSWER-01 | Ответ опирается на найденные факты. Существенные утверждения сопровождаются кликабельными цитатами. При нехватке данных агент называет конкретный пробел и отмечает подтверждённую часть, если она есть. | Проверить факты и цитаты по первоисточникам. Убрать ключевой фрагмент и проверить отказ или частичный ответ. |
| DIALOG-01 | Уточнение наследует уместные сведения из текущего диалога. Явные изменения в новом вопросе обновляют контекст. При критичной неоднозначности агент запрашивает нужные вводные. | Назвать вуз и кампанию, затем спросить «а на бюджете?». Следом поменять вуз и проверить ответ. Повторить вопрос в новом диалоге и проверить отсутствие переноса контекста. |
| SAFETY-01 | Тексты источников обрабатываются как данные. Инструкции из страниц и документов не меняют задачу агента и не инициируют действия. | Подать заранее подготовленный материал с посторонней инструкцией и проверить, что ответ по-прежнему опирается на факты и разрешённые источники. |
| UI-01 | Интерфейс поддерживает диалог, отображает ход запроса и результат, даёт открыть источники и начать новый диалог. | Пройти многоходовой сценарий в браузере. Проверить ожидание, ответ с цитатой, уточнение и ошибку соединения. |
| EVAL-01 | Для поиска и ответов есть воспроизводимые замеры с одинаковыми входами. Отчёт разделяет поиск, полноту доказательств, правильность ответа, дословность цитат и ошибки исполнения. | Прогнать один и тот же набор на двух версиях. Проверить результаты по доменам, длину выборки, время и стоимость. |

## Текущее состояние

| Часть | Состояние |
| --- | --- |
| Веб-бейзлайн | Firecrawl и DeepSeek V4 Flash через RouterAI. Есть CLI, FastAPI и проверка цитат по фрагментам. |
| Качество | Есть 54 веб-кейса, 6 проверок на неподходящие доказательства и 6 подготовленных сценариев уточнения. В [отчёте](metrics/eval-baseline.md) описаны живые прогоны и ограничения оценщика. |
| База знаний | Требования к сбору, структурированию, индексированию и обновлению относятся к следующему этапу. |
| Диалог и UI | Go и React подготовлены как каркас. Сохранение контекста и интерфейс диалога предстоит реализовать. |
| Устойчивость к prompt injection | Нужен отдельный защитный срез. Проверки отказа при недостатке данных покрывают другое поведение. |

## Доказательства для защиты

- Покажи один вопрос по RAG с проверяемой цитатой, одно уточнение без повторного ввода и один честный отказ.
- Приложи реестр источников и сводку охвата. Отдельно учитывай исходные документы и фрагменты индекса, чтобы размер разбиения не завышал объём данных.
- Сравни веб-бейзлайн и RAG на одних вопросах. Отдельно покажи точечные срезы на сроки, таблицы и неподходящие источники.

Способ хранения, стратегия обновления и необходимость живого веб-поиска поверх RAG остаются решениями реализации.
