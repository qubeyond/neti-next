# Отчёты по версиям

- Одна версия — один `eval-<версия>.md`. [Бейзлайн](eval-baseline.md) задаёт порядок таблиц, заголовки и названия метрик.
- Формируй отчёт из исходных JSON. Помести их в каталог прогона как `e2e.json`, `oracle.json`, `grounding.json` и, если был самостоятельный прогон поиска, `retrieval.json`. Команда проверяет режим и уникальность ID и пишет Markdown в stdout.
- В отчёте оставляй заголовки и таблицы. Для долей пиши `числитель/знаменатель (процент)`. Ставь `—` для неприменимой или незамеренной метрики, ноль — для измеренного нулевого результата.
- Сравнивай одинаковые кейсы, режимы, рубрики и лимиты. Условия изменённого этапа и количество новых поисковых вызовов должны быть видны в таблицах.
- Отличай ошибки провайдеров, неверные ответы и сбои оценщика. Стоимость бери из доступного `usage.cost`. Если списание неизвестно, оставляй отметку в таблице условий.
- Процедура прогонов и определения зачёта находятся в [evals/AGENTS.md](../../evals/AGENTS.md).
- Если замерялась устойчивость, добавь таблицу с числом попыток, строгим зачётом по перефразам и ложным предпосылкам, безопасными отказами и ложными ответами в ловушках, долей появившихся меток по каналу, сохранением строгого зачёта относительно чистого контроля и согласованностью повторов. Уточнения без реализованного интерфейса отмечай как незамеренные.

Из корня репозитория:

```bash
run_dir=evals/reports/your-run
uv run --project agent --locked python -m evals.render_metrics "$run_dir" \
  --version baseline --date 2026-11-20 --dataset expanded --answer-tokens 1536
```

Добавь `--robustness <путь к JSON>`, чтобы включить срез устойчивости и его стоимость.
