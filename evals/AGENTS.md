# Eval

Набор вопросов и воспроизводимые проверки поиска, генерации и цитирования. Формат результата и предыдущие версии описаны в [отчётах по версиям](../docs/metrics/AGENTS.md).

Принципы разделения проверок описаны в [ADR eval](../docs/adr/evals.md).

## Данные

- Входы находятся в `questions*.jsonl`, рубрики — в `gold/answers*.jsonl`, источники — в `gold/evidence*.json`. Соединяй записи по стабильным идентификаторам.
- Для фактов указывай официальный URL, точный фрагмент и его место в источнике. Для таблицы фиксируй строку и заголовок, для ссылки — адрес назначения `linked_url`.
- Разделяй домен и навыки. Похожие вопросы по одному источнику держи вместе при выделении закрытой выборки.
- В обычном прогоне передавай модели вопрос и результат поиска. Эталонные факты, критерии и URL доступны оценщику и диагностике. В `oracle` агент получает готовые выдержки и сведения о месте в документе.
- В `grounding` входные фрагменты специально не подтверждают спрашиваемый факт. Сценарии уточнения подготовлены отдельно для многоходового агента.

## Измерение

| Режим | Проверка |
| --- | --- |
| `e2e` | Firecrawl, контекст, генерация и цитаты в одной цепочке. |
| `retrieval` | Поиск и позиции известных URL без вызовов модели. |
| `oracle` | Ответ по проверенным фрагментам на те же вопросы, без нового поиска. |
| `grounding` | Отказ при недостаточных или неподходящих доказательствах. |

Офлайн-проверка из корня репозитория — `uv run --project agent --locked python -m pytest evals/tests`.

Примеры живых прогонов с сохранением исходного результата:

```bash
mkdir -p evals/reports
uv run --project agent --locked python -m evals.run_web_baseline \
  --mode e2e --domain housing --skill table --search-min-interval 7 --judge-max-tokens 3072 \
  > evals/reports/e2e-housing-table.json
uv run --project agent --locked python -m evals.run_web_baseline \
  --mode oracle --case sgups-dorm-difference > evals/reports/oracle-sgups-dorm-difference.json
```

- Для полного расширенного прогона опусти фильтры. `--dataset core|extension|expanded` задаёт набор. `--domain`, `--skill` и `--case` задают срез.
- `--reuse-search <отчёт>` переиспользует поисковую выдачу. `--fill-missing-search` разрешает новые поиски для недостающих кейсов. `--report <отчёт>` пересчитывает срез без API.
- `--judge-model` позволяет менять оценщика. Согласуй модель, рубрику, лимиты и вопросы для сравниваемых версий. Для проверки формата без оценки используй `--no-judge`.
- Для сравнения провайдеров используй `python -m evals.compare_search` с тем же префиксом uv. `--provider firecrawl --provider tavily` выбирает движки, `--enhanced` добавляет сокращённый запрос, `--all` включает исходную веб-выборку. Сохраняй одинаковые запросы и лимиты; блокировки учитывай отдельно.
- Живые прогоны берут настройки из `agent/.env` и расходуют квоту. Сохраняй сырые результаты в игнорируемый `evals/reports/` на время анализа. Итоги сохраняй отдельным отчётом версии.

## Правила оценки

- Строгий зачёт требует полного ответа с правильными фактами, применимыми доказательствами и валидными цитатами. Засчитывай другой официальный URL, если он доказывает тот же факт при тех же условиях.
- Дословность проверяй по предъявленному фрагменту. Применимость цитаты проверяй с учётом вуза, филиала, года, условий и единиц. В расчёте нужны доказательства исходных величин и правильный итог.
- Отделяй ошибки оценки, ошибочные факты и честный отказ. Проверяй по источнику спорные вердикты, особенно когда одна модель отвечает и оценивает.
