# Фронтенд

Рабочее пространство на React и TypeScript. Данные профилей, диалогов и файлов обслуживает Go. События WebSocket запускают перечитывание состояния.

Перед изменением стека или маршрутизации прочитай [ADR фронтенда](../docs/adr/frontend.md).

## Границы

- Исходники в `src/`, зависимости и версии — в `package.json`, `package-lock.json` и `.node-version`.
- Запрашивай `/api/…` у Go и `/agent/…` у агента по относительным адресам. Сверяй типы с сервисом-владельцем. Для новых вызовов проверяй состояния загрузки, успеха и ошибки.
- В dev проксируй через `vite.config.ts`, в prod — через nginx. Используй `BACKEND_UPSTREAM` и `AGENT_UPSTREAM` из фронтендового окружения. Передавай базовый URL без приклеенного маршрута.
- Для переноса на другой хост укажи доступные upstream-адреса. Для HTTPS сохраняй проверку сертификатов и имени. Диагностику DNS начни с резолвера контейнера.
- Отображай внешние тексты как текст. Храни ключи провайдеров в агенте. Браузеру передавай только публичные настройки.

## Запуск и проверка

Команды ниже выполняй из `frontend/`.

- Локальные проверки — `npm ci`, `npm run lint`, `npm run typecheck`, `npm run build`.
- Для запуска вне Compose выполни команду ниже. Она переопределяет имена контейнеров из `.env.example`. Страница на `127.0.0.1:8080` доступна автономно. Для проверки прокси нужны соответствующие HTTP-сервисы.
- Отдельный образ собирается как `docker build -t neti-frontend .`. При запуске передай свой `--env-file` с доступными адресами upstream и опубликуй порт контейнера `8080`.
- Для правок прокси проверь dev и prod через `make -C deploy smoke` из корня.

```bash
BACKEND_UPSTREAM=http://127.0.0.1:8000 AGENT_UPSTREAM=http://127.0.0.1:8001 npm run dev -- --host 127.0.0.1
```
