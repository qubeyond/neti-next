# Бэкенд

Самостоятельный Go-сервис. Текущий контракт — `GET /api/health`.

- Перед проектированием маршрута или хранения диалога прочитай [ADR бэкенда](../docs/adr/backend.md). При добавлении или изменении публичного маршрута обновляй OpenAPI по [правилам HTTP-контрактов](../docs/api-contracts.md).
- Храни серверный код и его зависимости внутри `backend/`. Добавляй продуктовые маршруты и хранилища по мере появления требований.
- Сохраняй healthcheck свободным от сетевых вызовов и ключей. Доступ извне в полном стеке идёт через прокси фронтенда.
- `BACKEND_PORT` описан в `.env.example`. Нативный Go-процесс читает значение из окружения, Compose передаёт его из файла. При смене порта в стеке сверь `BACKEND_UPSTREAM` фронтенда.

## Запуск и проверка

Из `backend/` выполни `gofmt -l .` и `go test ./...`, затем запусти `BACKEND_PORT=8000 go run .`. Без локального Go используй контейнер. Сборка выполняет проверку формата и `go test`.

```bash
docker build -t neti-backend .
docker run --rm --env-file .env.example -p 127.0.0.1:8000:8000 neti-backend
```

Ожидаемый ответ на `curl -fsS http://127.0.0.1:8000/api/health` — `{"status":"ok"}`. При изменении обратного прокси запусти общий smoke.
